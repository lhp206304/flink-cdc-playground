## 步骤 1：环境搭建 + 数据生成

### 练习目标
理解项目整体结构，搭建本地环境，能向 PostgreSQL 写入模拟业务数据。

### 对应代码
- 环境编排：`docker/docker-compose.yml`
- PG 初始化脚本：`docker/postgres/init/01-init.sql`、`02-replica.sql`
- 数据生成器：`data-generator/src/main/java/com/pipeline/generator/postgres/`
  - `PostgresDataGenerator.java` — 主入口
  - `PgDataWriter.java` — JDBC Batch 写入

### 核心知识点
| 知识点 | 说明 |
|--------|------|
| Docker Compose | 多服务编排（PG + Kafka + Kafka-UI） |
| PostgreSQL 逻辑复制 | `wal_level=logical`，CDC 的前提 |
| JDBC Batch | 批量插入提升吞吐 |
| HikariCP | 数据库连接池 |

### 操作步骤
1. `cd docker && docker-compose up -d`
2. 查看 PG 表结构：`docker exec pg-cdc psql -U postgres -d ecommerce -c "\dt public.*"`
3. 查看维表：`docker exec pg-cdc psql -U postgres -d ecommerce -c "\dt base.*"`
4. 运行 PG 数据生成器（见 README 步骤 4），数秒后 `Ctrl+C` 停止
5. 验证数据：`docker exec pg-cdc psql -U postgres -d ecommerce -c "SELECT count(*) FROM public.orders;"`

### 思考题
- 为什么 PG 需要开启 `wal_level=logical`？不开启会怎样？
- 数据生成器为什么用 JDBC Batch 而不是单条 INSERT？
- `base.users` 和 `base.products` 为什么不通过生成器写入，而是初始化脚本灌入？

## 步骤 2：CDC 整库同步到 Kafka

### 练习目标
用 Flink CDC 3.x Pipeline API（YAML 声明式）将 PostgreSQL 业务表的变更实时同步到 Kafka。

### 对应代码
- 主入口：`flink-jobs/src/main/java/com/pipeline/flink/cdc/PostgresCdcToKafka.java`
- Pipeline 定义：`flink-jobs/src/main/resources/pipelines/postgres-to-kafka.yaml`

### 核心知识点
| 知识点 | 说明 |
|--------|------|
| Flink CDC Pipeline API | 声明式定义源→变换→目标，无需写 Java 代码 |
| Debezium JSON 格式 | CDC 消息的标准格式（before/after/source/op 等） |
| 逻辑解码 | PG 通过 WAL 日志捕获变更 |
| Exactly-Once | CDC 端到端精确一次语义 |

### 操作步骤
1. 查看 YAML 配置，理解 `source` → `sink` 的路由规则
2. 运行 CDC 作业（见 README 步骤 5）
3. 查看 Kafka topic 列表：`docker exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list`
4. 消费一条 CDC 消息观察格式：
   ```bash
   docker exec kafka /opt/kafka/bin/kafka-console-consumer.sh \
     --bootstrap-server localhost:9092 --topic cdc.orders --from-beginning --max-messages 1
   ```

### 验证方法
- Kafka 出现 `cdc.orders`、`cdc.payments`、`cdc.order_items`、`cdc.base_region` 等 topic
- 每个 topic 都能消费到 Debezium JSON 格式的消息

### 思考题
- YAML 中 `route` 规则是如何把 PG 表名映射到 Kafka topic 名的？
- CDC 消息的 `op` 字段有哪些值？分别代表什么操作？
- 为什么用 YAML 声明式而不是 Java 编程式做 CDC 同步？

## 步骤 3：Kafka 消费 + 反序列化 + DLQ

### 练习目标
用 Flink KafkaSource 消费 CDC topic，自定义反序列化器解析 Debezium JSON，脏数据侧输出到 DLQ。

### 对应代码

### 核心知识点
| 知识点 | 说明 |

| DeserializationSchema | 自定义字节→对象反序列化 |

5. 制造一条脏数据到 Kafka，观察是否进入 DLQ topic

### 验证方法

- 非法 JSON 消息被侧输出到 `dlq.cdc` topic

### 思考题

## 步骤 4：双流 JOIN（订单 + 支付）

### 核心知识点
| 知识点 | 说明 |

| ValueState | 键控状态，缓存先到达的流数据 |

### 操作步骤

## 步骤 5：维表关联（Broadcast + AsyncIO）

### 练习目标
- 用 **Broadcast 广播流**关联小维表（region）
- 用 **AsyncIO + JDBC** 关联中维表（users）

### 对应代码
- Broadcast 关联：`flink-jobs/src/main/java/com/pipeline/flink/kafka/enrichment/RegionBroadcastJoin.java`
- AsyncIO 关联：`flink-jobs/src/main/java/com/pipeline/flink/kafka/enrichment/UserAsyncIoJoin.java`
- AsyncIO 基类：`flink-jobs/src/main/java/com/pipeline/flink/common/JdbcAsyncLookupFunction.java`

### 核心知识点

**Broadcast 广播流（小维表）：**

| 知识点 | 说明 |
|--------|------|
| BroadcastState | 广播状态，所有并行子任务共享同一份维表数据 |
| MapStateDescriptor | 广播状态描述符，定义 key-value 结构 |
| connect + broadcast | 主流连接广播流 |

**AsyncIO（中维表）：**

| 知识点 | 说明 |
|--------|------|
| AsyncDataStream.unorderedWait | 异步 I/O 算子，不阻塞主流 |
| RichAsyncFunction | 异步函数基类，`asyncInvoke` 回调返回结果 |
| JDBC 连接池 | HikariCP，异步查询维表 |
| 超时 + 并发控制 | 防止异步请求堆积 |

### 操作步骤
1. 阅读 `RegionBroadcastJoin`，理解：
   - `processBroadcastElement`：接收维表 CDC 变更，更新 BroadcastState
   - `processElement`：主流订单查 BroadcastState 补 region_name
2. 阅读 `UserAsyncIoJoin` + `JdbcAsyncLookupFunction`，理解：
   - `asyncInvoke` 如何发起异步 JDBC 查询
   - 超时和并发如何配置
3. 运行 DWD 作业，验证宽表中 `region_name`、`user_name`、`user_level` 字段已富化

### 验证方法
- 宽表中 `region_name` 为中文地区名（如"美国东部"）
- 宽表中 `user_name`、`user_level` 不为空

### 思考题
- 为什么 region 用 Broadcast，而 users 用 AsyncIO？能互换吗？
- Broadcast 维表如果数据量很大（百万级），会有什么问题？
- AsyncIO 的并发数设多少合适？受什么限制？

### 练习目标
将 DWD 宽表写入 Iceberg 数据湖，理解 Iceberg Catalog、Table API、Kryo 序列化等关键机制。

### 对应代码

- Kryo 序列化器：`flink-jobs/src/main/java/com/pipeline/flink/common/FlinkWriteResultKryoSerializer.java`

### 核心知识点
| 知识点 | 说明 |
|--------|------|
| Iceberg Catalog | 表目录管理（HadoopCatalog 本地文件系统） |
| Table API | DataStream → Table → INSERT INTO Iceberg |
| Schema 定义 | `Schema.newBuilder()` 定义表结构 |
| Kryo 自定义序列化 | Iceberg `FlinkWriteResult` 的特殊序列化处理 |
| Checkpoint 提交 | Iceberg 在 Checkpoint 时提交快照 |

### 操作步骤
1. 阅读 `IcebergSinkFactory`，理解：
   - Catalog 如何创建（`IcebergSinkFactory.createTableEnv`）
   - 表如何自动创建（`CREATE TABLE`）

3. 运行 DWD 作业，查看 Iceberg 数据目录

### 查看数据
```bash

python3 -c "

t = pa.concat_tables([pq.read_table(f) for f in glob.glob('*.parquet')])
print(f'总记录数: {t.num_rows}')

```

### 思考题
- 为什么 Iceberg 需要自定义 Kryo 序列化器？默认序列化器有什么问题？
- Iceberg 的数据可见延迟由什么决定？（提示：Checkpoint 间隔）
- `CREATE TABLE` 和 `INSERT INTO` 是 Table API 的哪两个阶段？

## 步骤 7：生产增强

### 练习目标
理解 Flink 生产级配置：Checkpoint、状态后端、重启策略、DLQ。

### 对应代码
- 环境配置：`flink-jobs/src/main/java/com/pipeline/flink/common/StreamEnvBase.java`
- DLQ 接线：`DwdOrderPaymentJob.java` 步骤 10
- DLQ Sink：`KafkaSourceFactory.buildDlqSink()`

### 核心知识点
| 知识点 | 说明 |
|--------|------|
| Checkpoint | 分布式快照，实现容错恢复 |
| Exactly-Once | 端到端精确一次语义 |
| RocksDB 状态后端 | 状态存磁盘，支持大状态 + 增量 Checkpoint |
| 重启策略 | 作业失败后自动重启（固定延迟策略） |
| DLQ | 死信队列，脏数据不阻塞主流 |

### 操作步骤
1. 阅读 `StreamEnvBase.createEnv()`，逐项理解配置：
   - Checkpoint 间隔、超时、最小间隔、并发数
   - 语义模式（EXACTLY_ONCE）
   - 外部化 Checkpoint 保留策略
   - RocksDB + 增量 Checkpoint
   - 固定延迟重启策略
2. 阅读 DLQ 接线代码，理解侧输出如何写入 Kafka DLQ topic
3. 运行 DWD 作业，观察日志中 Checkpoint 成功的记录

### 验证方法
- 日志中出现 `Checkpoint ... completed` 记录
- 故意往 Kafka 写入非法 JSON，`dlq.cdc` topic 中能消费到该消息

### 思考题
- Checkpoint 间隔设太短或太长分别有什么影响？
- RocksDB 相比 Heap 状态后端有什么优缺点？
- 外部化 Checkpoint 保留策略 `RETAIN_ON_CANCELLATION` 是什么意思？

## 常见问题速查

| 问题 | 解法 |
|------|------|
| `ClassNotFoundException: SimpleUdfStreamOperatorFactory` | 用 `java -cp` 而非 `mvn exec:java` |
| `InaccessibleObjectException: java.nio.ByteBuffer` | 加 `--add-opens java.base/java.nio=ALL-UNNAMED` |
| Iceberg Kryo 序列化 `NullPointerException` | 注册 `FlinkWriteResultKryoSerializer` |
| `LocalDateTime` 反序列化失败 | PostgreSQL 用空格分隔，需自定义 Jackson 反序列化器 |
| `too many clients` | 调小 HikariCP `maximumPoolSize` |
